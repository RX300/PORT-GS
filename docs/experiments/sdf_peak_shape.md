# SDF亮点形状：邻域监督与提示编码

日期：2026-09-23。状态：两候选各3000步训练、同16训练帧评价、首4帧邻环审计及最终参数审计全部结束。
`context`减轻局部泛白并改善部分亮点定位，但整体仍低于uniform和主GS；`hint_encoding`未改善质量。
两者均不设为默认，不推进official-test。下一步选择训练覆盖/预算诊断，尚未启动。

## 已有证据与两个独立假设

前轮 [亮点采样对照](sdf_peak_sampling.md) 已完成。同16个已见训练视图上，
25%峰采样使GT峰处RGB MAE从.343188降至.114115，但PSNR从23.284552降至21.152530，
亮点局部对比仍只有GT的13.63%。首4帧的11×11峰邻环neutral正向误差从.032172升至.177974，
显示亮度向周围非峰像素扩散。它不是细小高光恢复成功，也没有证明唯一根因。

本轮围绕共同的25%峰采样控制，分别检验两个机制：

1. `context`：保留峰监督强度，增加峰周围非峰邻环的射线监督，检验局部负样本覆盖能否抑制宽亮斑。
2. `hint_encoding`：采样不变，仅给现有高光提示添加频率编码，检验更易表达快速角度变化的输入基是否改善拟合。

两候选各自相对共同控制构成单项干预；`context`与`hint_encoding`之间同时存在采样和表达差异，
不能把它们彼此称为单变量对照，也不将两种机制在本轮组合。

## 两组参数及射线配额

| 分支 | peak fraction | peak-context fraction | hint encoding | 峰/邻环/前景/定义域配额 |
|---|---:|---:|---|---|
| 已完成控制 `peaks` | .25 | 0 | 关闭 | 128 / 0 / 192 / 192 |
| `context` | .25 | .25 | 关闭 | 128 / 128 / 128 / 128 |
| `hint_encoding` | .25 | 0 | 开启 | 128 / 0 / 192 / 192 |

CLI参数为 `--sdf-volume-peak-fraction`、`--sdf-volume-peak-context-fraction`、
`--sdf-volume-hint-encoding`。所有采样有放回；配额是抽样次数，不是唯一像素数。
峰/邻环池需与有效SDF定义域取交集，其余前景/定义域池允许与它们重叠。
某专用池为空时，其未使用预算回到剩余的前景/定义域各半分配；前景为空时余量全给定义域。

邻环由原生512px训练GT的 `neutral_peak_mask` 定义：

```text
ring = (max_pool2d(peak, kernel=11, stride=1, padding=5) > 0)
       & ~peak & (target_alpha > .9)
```

这是Chebyshev半径5的11×11邻域，不是半径11；不根据模型预测或test生成掩码。
训练GT只控制射线抽样，不是推理时辐射网络的额外输入。

两候选都保持逐射线RGB L1、mask及有效depth/normal一致性项。
`context`是显式重权目标，不做逆概率补偿；变化同时作用于这些损失的采样分布，不能称无偏采样。
距离场冻结但sharpness学习，所以alpha、合成深度/法线与沿ray权重仍可能改变。
`context`减少全局前景/定义域配额，也可能损害远离峰的拟合；必须同时报告远处前景和全图结果。

## 提示编码的精确定义与文献边界

现有提示保留为每个体采样点的3维停止梯度特征：

```text
h_b = log1p(b * (1 - clamp(dot(normal, half_vector), 0, 1))) / log1p(b)
b = [100, 1000, 10000]
```

候选只新增 `sin(2^k*h_b)`、`cos(2^k*h_b)`，`k=0,1,2,3`，不乘π。
24维编码经 `Linear(24,128,bias=False)` 加到现有第一层Linear之后、ReLU之前，
投影权重全0初始化，新增3072个参数。原94维输入和其中3个原提示均保留；
位置、wi/wo编码、光源条件、辐射正值输出、点光衰减及体采样算法不改变。

依据是NRHints对提示做频率编码的设计，而非复现其完整提示。
原文将高光视为稀疏高频输运，原官方实现先从每条ray的体权重平均法线/hit point计算
4个粗糙度的Cook–Torrance/GGX响应，再沿ray复制并编码；不是power-exponent提示，也不是此处log变换。
本轮仍使用逐采样点log提示，保留停止梯度。
官方编码使用无π的 `[1,2,4,8]`，本轮只沿用这一编码频率选择。
来源：[NRHints论文§3](https://arxiv.org/html/2308.13404#S3)、
[提示计算](https://github.com/iamNCJ/NRHints/blob/0da5b82b851622a4d61aeb35e79fda889efe0441/models/neus_hint_model.py#L581-L616)、
[提示PE接入](https://github.com/iamNCJ/NRHints/blob/0da5b82b851622a4d61aeb35e79fda889efe0441/fields/reflectance_network.py#L41-L53)、
[无π编码](https://github.com/iamNCJ/NRHints/blob/0da5b82b851622a4d61aeb35e79fda889efe0441/fields/encodings.py#L155-L175)。

这不是再次替换解析GGX材质或强制用SDF法线直接着色。
即使拟合变好，也只支持新的特征参数化/优化在本协议下有帮助，不证明旧MLP在数学上无法表示尖峰。
若失败，也不能单独否定编码，法线误差与体积分混合仍可能限制输出。
NRHints自身也指出法线误差会令尖锐反射的提示/重参数化失败。
[原文§6](https://arxiv.org/html/2308.13404#S6)

另一个查证边界是GOGS的球面Mip方向补偿在新灯光重光照时明确禁用；
本轮不把它用作重光照恢复方案，也不加入固定照明的视角残差。
[GOGS §4.2](https://arxiv.org/html/2508.14563v1#S4.SS2)

`context`相对控制的PSNR提高.730461dB，16帧均提高；峰对比/GT由.136336提高到.153857，
定位recall从15.42%提高至22.62%，precision从20.36%提高至24.35%。
代价是峰RGB MAE增加31.06%，16帧都变差，SSIM和alpha误差也未改善。
因此邻环监督带来局部亮度/定位取舍，不是所有质量指标同时提升。
整体PSNR仍低于uniform约1.402dB、主GS约4.195dB，峰对比仍远低于主GS的.451671，
不足以认定准确细小高光已恢复；不将峰处单项MAE低于主GS解释为整体胜出。

`hint_encoding`的峰RGB MAE相对控制仅下降1.07%，但PSNR下降.165715dB，
峰对比、precision、recall均下降。其预测峰5963个，其中1050个匹配GT邻域；
控制对应6136/1249个，`context`为5783/1408个。
新的频率编码在这个单seed/3k预算下没有带来质量收益，记录为负结果，不继续组合或默认启用。
这不证明所有方向编码均无效，也不证明当前模型已达表达上限。

`uniform`只有15个预测峰像素，其precision=1仍不代表实用的峰恢复，须与不足1%的recall一起看。
本轮没有主GS、真实几何或未见灯光泛化改善证据，不推进official-test评价。

## 覆盖审计与下一步决策

`sampling_coverage.json`根据seed0和canonical选帧规则重建3k步顺序，
并与全部31个已记录步核对。该轮访问559/562帧，帧219、250、344在新增3k步中未抽到；
不能由此声称源模型从未见过这3帧，源模型已经学习全部562帧。

训练GT共有212982个亮点代理像素。3k步的专用峰配额为384000次，
`384000 / 212982 = 1.802969`，即每个峰像素池成员平均约1.803次专用配额抽样。
按逐帧访问次数及帧内有放回抽样计算，期望约24.596%的峰像素未被专用峰配额选中。
这不是实测unique覆盖率：没有记录逐像素去重计数，普通前景/定义域射线还可额外命中峰，
源网络也已拟合这些帧并能共享像素间信息。
覆盖统计不是收敛测量，不能证明采样预算已被确定为主瓶颈。

下一步暂不增加新结构，选择从同一geometry_grid源模型、同context采样比例出发，
通过增加射线与训练覆盖做预算诊断，检验当前头是否仍能改善窄峰与邻环误差。
新预算须明确记录每步射线数、更新步数及总射线数；预算不同的结果不能包装成等预算方法胜出。
继续使用相同fit评价协议，同时看峰、邻环、远处前景和全图，不使用test调参。
此下一轮尚未启动，本文不预定其结果，也不把本轮局部改善当成研究目标完成。
